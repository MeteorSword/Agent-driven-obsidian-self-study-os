# SelfStudyOS 版本标识

这个文件回答一个问题：**你手上这个 Vault 是从哪个版本开始的。**

它不在学习流程里，agent 只在两种情况下读它：

1. 你需要升级时，判断起点版本与需要执行的迁移步骤。
2. 你报告问题时，让对方知道你跑的是哪个版本。

## 当前版本

```text
selfstudyos_version: 1.1.0
released: 2026-10-30
schema: 1
```

## 两个"版本"的关系

| 位置 | 内容 | 谁读 |
|---|---|---|
| 本文件 | 版本号 + 升级说明 | 人 |
| `.selfstudyos/index.json` | 逐文件指纹 + 上次修改版本 | 升级器 |

**机器真值以 `.selfstudyos/index.json` 为准**；本文件的版本号必须与它一致，不一致时以 `.selfstudyos/` 为准并修正本文件。

没有 `.selfstudyos/index.json` 说明这个 Vault 来自 v1.0 之前，需要用 `scripts/migrate-v0.3-to-v1.0.ps1` 做一次性迁移。

## 版本约定

| 编号 | 含义 | 兼容性 |
|---|---|---|
| `1.0.0` | 主版本 | 主版本变化可能要求迁移（目录结构或规则语义变更） |
| `1.1.0` | 次版本 | 只新增能力，旧 Vault 可直接用新模板，无需迁移 |
| `1.0.1` | 修订 | 文档与措辞修正，无结构变化 |

`schema` 是**文件格式**的版本，与产品版本分开：只要 `.md` 的必备字段（frontmatter 的 `type`、索引表的列）发生变化，`schema` 就 +1。

## 升级怎么做

1. **先只读扫描**：运行仓库里的 `scripts/migrate-v0.3-to-v1.0.ps1`，得到四类清单（框架文件 / 用户数据 / 生成产物 / 私人资料）与冲突项。它不写你的 Vault。
2. **人工确认冲突**：你自己改过的框架文件不会被自动覆盖，需要逐个决定保留哪份。
3. **分批合并**：先框架文件，再 AgentMemory，再资料路由，最后规则文件。每批前后比对哈希。
4. **留档**：升级完成后在本目录建 `migration_<YYYY-MM-DD>.md`，写清触发原因、执行阶段、回滚命令与后续验证计划。

## 不要做的事

- 不要用新模板**整体覆盖**旧 Vault。
- 不要删除旧位置的资料目录，直到你确认新位置的副本可读。
- 不要把系统升级记录写进 `Review/progress.md` 或课程 `progress.md`——那两页只记学习证据。
