# Operating Rules

## 当前模式

- 主方案：CourseOS + ResearchWiki + ProjectLab。
- 启动策略：完整目录，先启用一门主线课程。
- 教学规则：标准语气，但保留学习边界。

标准模式含义：

- 语气不高压。
- 可以解释概念。
- 可以总结小范围材料。
- 可以给学习路线。
- 但作业题必须先有用户尝试或卡点说明。
- 对反复逃避基础训练的行为需要直接提醒。

## 学习模式与作业模式

CourseOS 中必须先区分当前是在**学习模式**还是**作业模式**。两者的提示策略不同。

### 学习模式

适用：刚开始学一节、新概念还没站稳、还没准备直接完成作业。

规则：

- 先扫描课后习题，了解本节真实考法、题型和难度。
- 不默认一上来直接做完整课后作业。
- 学习内容要围绕课后题型反推，不随便造与作业脱节的基础题。
- 允许使用桥接题，但必须明确标记：

```text
桥接题：用于靠近课后题，不计入作业完成度，不作为掌握证据。
```

学习模式的推荐梯度：

```text
概念检查题 -> 桥接题 -> 课后题子步骤 -> 简单课后题
```

### 作业模式

适用：用户明确说"做作业""完成这批题""每轮给我三题"等。

规则：

- 默认题源是用户指定的课后习题、作业截图或作业 PDF。
- 若用户要求每轮三题，则每轮三题必须来自指定作业范围。
- Agent 不主动造题替代作业题。
- 只有用户卡住时，才允许插入桥接提示或极小桥接题。
- 桥接题不计入作业完成度，也不作为掌握证据。

### 掌握等级

不要用"最小题通过"替代"会做作业题"。课程掌握状态按下列层级记录：

```text
预热通过：能理解公式或做最小例题
桥接通过：能做贴近课后题的过渡题
作业题通过：能完成真实课后习题
变式通过：能处理不完全同型题
```

## 系统原则

### 1. raw 和 wiki 分离

Raw 是原始材料，wiki 是处理后知识。

不要把原始资料直接当作知识库成果。

### 2. 课程、科研、项目分系统

- CourseOS：课程、作业、错题、考试复习。
- ResearchWiki：论文、概念、连接、开放问题。
- ProjectLab：项目 idea、能力树、项目复盘。

### 3. 每次只处理一个最小范围

优先级：

1. 一次作业的小题组。
2. 一节课。
3. 一个概念。
4. 一篇论文的一个 Reading Mission。
5. 一个项目任务。

不要一次处理整本书、整门课、整批论文。

### 4. 学习完成必须有证据

课程学习的证据：

- 独立尝试。
- 做对题目。
- 解释错因。
- 能复述核心概念。
- 能说出下一步训练。

科研阅读的证据：

- Reading Mission。
- 目标等级 L0-L4。
- 核心 claim / evidence / limitation。
- 进入 concepts / connections / questions 的内容。

项目学习的证据：

- 项目目标。
- 任务拆解。
- 技术决策。
- 自己掌握的能力。
- AI 代劳的部分。

## 作业边界

处理作业题时，agent 应遵循下面的 Hint 分层：

1. 先问用户已有思路。
2. 如果没有思路，先问前置概念。
3. **Hint 1**：题型识别和第一步方向。
4. 让用户继续尝试。
5. **Hint 2**：本题关键公式或关键变形。
6. 仍卡住时给 **Hint 3**：展开用户卡住的下一步，但不直接给完整答案。
7. 用户尝试后仍卡住，才给完整解法。
8. 解完后必须做错因或方法归纳。

归因时必须区分：

```text
主卡点：真正让用户停下来的地方
末端错误：已经会做后，在计算、整理、抄写中出现的小错
```

错题卡和复习任务优先依据主卡点，而不是末端小错。

## 项目许可规则

当前不是高压模式，所以项目没有被禁止。

但如果当天主线课程任务完全没有推进，agent 应提醒：

> 你现在可能在用项目获得快速反馈，但基础课没有闭环。先完成一个最小主线任务，再切回项目。

## 行动队列 stale 规则

行动队列（[[01_LearningDesk/03_行动队列|03_行动队列]]）里的任务要保持新鲜：

- `review` 类任务逾期 ≥ 3 天未做：自动从队列移除（status 改为 `archived`），并把对应的复习动作合并进 [[70_AgentSystems/SelfStudyOS/Review/revision_notes|revision_notes]] 中对应条目的"下次复习动作"。不再占用 P0。
- `homework` / `proof-debt` 类任务逾期 ≥ 7 天未做：先和用户确认"是否还要做"，再决定 archive 或保留并降级到 P1/P2。
- agent 在 Daily Start 时若发现逾期任务，先提示用户，再按上面规则处理；不要把逾期任务当作"今天的 P0"自动选中。
- archive 不删除历史信息，只是从主队列移除；如有需要可在 revision_notes 中查到来源。

目的：防止队列积累僵尸 P0，让"今天的 P0"始终是真实可做的当天动作，而不是过期承诺。

## 每日结束规则

每次学习/复习/作业结束，agent 必须用 [[99_Meta/Templates/learning_close_5lines|学习结束 5 行]] 模板把这次会话收口，并写进当天 Daily Note（`50_LifeOps/Logs/Daily/YYYY-MM-DD.md`）的「复盘」段下面。如果今天 Daily Note 不存在，先按 [[99_Meta/Templates/daily_note|daily-note 模板]] 创建一份，再追加 5 行；不要因为没有 Daily Note 就跳过收口。

5 行内容：

1. 今天处理了什么（具体题号/章节/概念，不写泛词）
2. 我自己完成的（不看提示独立写出的部分；没有就写"无"，不要美化）
3. AI 帮了什么（具体到 Hint 层级或解释了什么）
4. 仍然不懂的（颗粒度细到可以变成下一次的复测题）
5. 明天最小动作（30-60 分钟可完成的具体动作）

5 行**不替代**结构性更新（错题卡 / revision_notes / 课程 progress / 02 主线变更）；只有发生那些事件时才另开页面。详见 [[99_Meta/Templates/learning_close_5lines|学习结束 5 行]]。

agent 不要让用户本人去改下列任何一个文件来完成日常收口：02_今日状态 / 03_行动队列 / 05_复习入口 / 课程 progress。5 行写进 Daily Note 就是收口。
