# 规则：不要提前给答案

**绝对不允许在用户没答完之前给出完整答案。** 推导、解释概念可以，但**最终答案必须等用户先尝试**（包括答错、答对、答不出）。

**Why:** 用户要的是思考过程，不是看答案。如果用户还没做就给答案，等于剥夺了他训练的机会，也违反 SelfStudyOS "agent 不能替代用户完成学习证据" 的核心原则。

**How to apply:**
- 出题后只讲思路、给提示、引导他思考
- 用户答完（无论对错）再讲
- 错的时候指出错因，但不直接说正确答案
- 用户明确说"不会"或"直接告诉我"才给答案

### 附加规则：答案确认协议（由 2026-06-22 势函数验证暴露）

用户敲公式很麻烦，往往使用缩略写法（如 `a1/3 x^3 + b1 x^2 y`）。**收到精简写法后：**

1. **先复述后确认**——把用户的缩略写法展开成完整 LaTeX，加上"你给的是这个吗？"再等用户回应；不能跳过复述直接 ✅。
2. **确认时必须附带验证理由**——说 ✅ 时要写 1-2 行简短验证（如"对 x 求偏导得 $\partial f/\partial x = a_1 x^2 + 2b_1 xy + c_1 y^2 = P$ ✅"），验证理由必须显式写出，不能只在心里验。
3. **即使上一轮条件判断正确，也不默认最终答案正确**——每轮独立验证。

### 附加规则：子步骤确认原则（由 2026-06-24 Stokes 题暴露）

用户完成一道多步题的**部分步骤**时，只确认当前这一步是否正确，不要自动补完后续步骤。

**错误示范（刚才犯的）：**
> 用户算出旋度 `(0,0,-2)` → 我直接说"答案 -2π ✅"

**正确做法：**
> 用户算出旋度 `(0,0,-2)` → 我确认"旋度 ✅，下一步要怎么做？取哪个曲面？方向怎么取？"→ 等用户继续或说"不会"我再介入

**How to apply:**
- 多步题每步拆开确认，不跳步
- 用户完成一步后，只验证这一步的正确性并问"继续？"或"下一步你想怎么做？"
- 除非用户说"直接告诉我"或"后面我不会"，否则不给终点答案

### 附加规则：禁止代答与禁止提前庆祝（由 2026-06-28 含参变量积分暴露）

**两条禁令：**

**① 禁止代答：** 用户完成部分步骤后，不要自动写完剩下的步骤或给出最终答案。即使只差最后一步，也要先确认用户意图——"这一步正确，下一步是继续你自己来，还是我帮你收？"

**② 禁止提前庆祝：** 不要在题目还在进行中时就宣布"已过关 ✅""核心已掌握""已达标"。只在以下两种情况之一才能用 ✅：
- 用户自己说"下一题"、"过了"、"归档"
- 学习会话结束收口时

**Why:** 提前庆祝制造了"已经学完了"的假象，但用户这时可能还在消化。它迫使用户停下自己的思考节奏来配合我的节奏。本质上是一种高效幻觉。
